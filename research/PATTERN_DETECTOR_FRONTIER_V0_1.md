# D01 DL-030 — Detector-Frontier Negative Controls V0.1

Updated: 2026-10-03 Asia/Taipei
Status: CLASS_A_RESEARCH_ONLY / OUTCOME_BLIND / HARD_NEGATIVE_CONTROL_DESIGN / FORMAL_CORE_LOCKED

## 1. Purpose

DL-027 uses generic non-anchor pseudo-zones.
DL-028/029 add salience matching.

A stronger falsification asks:

Do structurally confirmed MAJOR zones behave differently from candidates that are already structurally salient but fall on the non-MAJOR side of the frozen detector frontier?

This is a hard negative-control design.

It is NOT a causal Regression Discontinuity design.

## 2. Why not call this RDD

The k=3 ATR MAJOR threshold is a deterministic detector rule.

Objects just above/below the threshold are not randomly assigned by the market.

Other path properties can vary with the selection margin.

Therefore:
- no local-randomization claim;
- no automatic causal interpretation at zero margin;
- no bandwidth mining;
- no "threshold causes effect" statement.

The frontier is a strong comparability device only.

## 3. Frozen detector hierarchy

Reuse without retuning:
- MICRO k=1;
- BASE k=2 / 120 eligible sessions;
- MAJOR k=3 / 260 eligible sessions;
- lagged ATR frozen from the prior completed bar at leg start;
- confirmed pivotAt / confirmedAt causality;
- TECHNICAL_CONTINUITY / symbol-session guards.

No detector setting changes from outcomes.

## 4. Frontier family F1 — BASE_CONFIRMED_MAJOR_REJECTED

Primary feasible hard negative control.

Candidate must:
- be a causally confirmed BASE structural object under k=2;
- be evaluated at the same asOf / semantic space;
- not qualify as the corresponding MAJOR object under k=3;
- preserve its BASE identity/version;
- have sufficient 260-session MAJOR evaluation history/provenance to know the rejection is real rather than UNKNOWN.

Required continuous diagnostics:
- BASE swing amplitude ATR;
- MAJOR required amplitude ATR (=3 under frozen detector);
- selectionMarginATR = observedRelevantAmplitudeATR - 3;
- BASE age / anchor spacing;
- price extremeness;
- zone width ATR;
- O/M/S salience descriptors from DL-028 where available.

Interpretation:
this candidate is structurally real at a lower frozen scale but not confirmed MAJOR.

It is stronger than an arbitrary pseudo-price control.

## 5. Frontier family F2 — MAJOR_SINGLE_GATE_REJECT

Future stronger control if the detector exposes proposal-level diagnostics.

Candidate must:
- be generated by the same MAJOR proposal path;
- pass all frozen non-amplitude gates;
- fail exactly one frozen selection gate;
- failed gate and continuous margin recorded before outcomes;
- no later outcome used to decide whether the proposal counts.

V0.1 preferred failed gate:
MAJOR_DIRECTIONAL_CHANGE_K3.

Required:
failedGateCount = 1.

If the current detector cannot prove this:
F2_STATUS = INSTRUMENTATION_REQUIRED / NOT_AVAILABLE,
not reconstructed from future charts.

## 6. Selection-margin semantics

For the k=3 amplitude gate:

selectionMarginATR =
observedDirectionalChangeATR - 3.

Interpretation:
- >0: exceeds the frozen MAJOR amplitude threshold;
- =0: exactly at detector threshold;
- <0: below threshold.

The margin is continuous descriptive provenance.

No "near threshold" cutoff is frozen in D01.

D16 may later preregister a local-support analysis if sufficient common support exists.

## 7. Same-cutoff requirement

True MAJOR and frontier control must be compared using information available by the same immutable parent cutoff.

Prohibited:
- using a BASE object only because it later failed;
- using later bars to calculate the detector margin;
- using final full-history pivots to reconstruct a rejected candidate;
- upgrading/downgrading candidate class after outcome.

## 8. Scale identity is not a vote

A BASE object and a MAJOR object derived from overlapping anchors remain related representations of one PRICE_OHLC history.

Do not count:
BASE confirmed + MAJOR confirmed
as two independent confirmations.

Frontier controls exist for mechanism falsification only.

## 10. Detector-frontier contamination

A BASE-rejected control can later become MAJOR under new future data.

Historical class remains:
BASE_CONFIRMED_MAJOR_REJECTED_AS_OF_T.

Do not retroactively remove it.

A future MAJOR confirmation is later evidence, not proof the historical control was invalid.
